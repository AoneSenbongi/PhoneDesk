# PhoneDesk

## 要求
- Windowsのexeとして提供する。AndroidをUSB接続すると画面を自動表示する。
- マウス操作とPC接続キーボードの入力をAndroidへ反映する。
- USBデバッグはユーザーが有効化済み。ADBの初回許可は端末側で行う。
- ロック画面が操作可能な端末では、通常のPIN・パスワード・パターン操作で解除する。認証情報は保存しない。

## 実装方針
- 「右回転」はwm fixed-to-user-rotation enabledとuser-rotation lock 1でAndroid本体を横向きにする。元の回転モードをAndroid側の独立した復帰プロセスに保持し、「元に戻す」・切断・アプリ終了で元の設定へ戻す。PC表示だけの回転は使わない。映像PIDとUHIDは維持し、実端末の回転に映像比率を追従させる。
- PC出力時はIAudioEndpointVolumeでWindows全体の現在の音量へ同期する。Windows側の変更を2秒周期で取得し、アプリ側の操作も同じマスター音量へ反映する。scrcpy音声セッション固有のゲインは100%とし、過去のアプリ別音量が二重に掛からないようにする。スマホ出力時は従来の端末音量を操作する。
- クリップボードはスマホ→PCのテキストのみ。ユーザーがスマホでコピーしたことによる変更をAndroid ClipboardManagerの通知で受け取り、PCへ反映する。開始時の既存内容は取得しない。PCのクリップボードは読み取らず、scrcpyはno-clipboard-autosyncを維持してPC→スマホの自動転送を止める。画像・ファイルは対象外。
- 詳細に「PCから音を出す」のスイッチを配置し、初期値は有効、HKCU/Software/PhoneDesk/PcAudioへ保存する。映像・UHIDは常時no-audioで維持する。音声は別のno-window / audio-source=playbackプロセスで転送する。接続直後は映像の埋め込みが完了してから音声を開始し、同一端末へのサーバー転送の競合を避ける。スイッチは音声プロセスだけを開始・停止し、映像PID・SDL HWND・UHID接続を維持する。スイッチは標準BUTTONのowner-drawで描画し、クリック・Spaceによる切替に対応する。PC出力時はWindowsの既定再生デバイスのマスター音量を0〜100で操作し、端末の音量は変更しない。端末出力時だけ従来の端末メディア音量を操作する。音声転送はAndroid 13以降のplaybackキャプチャを使用し、キャプチャを拒否するアプリは対象外。
- 端末の回転はscrcpyのTexture通知から検出し、初期映像の正確な縦横比を入れ替えて外側ウィンドウへ反映する。通常表示・最大化・左側詳細に対応する。詳細表示時は操作部品が収まる高さ436pxを確保し、モニターの範囲内で映像を拡大する。
- コンパネの「音量−」「音量＋」と、その下のスライダーで選択端末のメディア音量を操作する。AudioControl.javaからIAudioServiceを呼び、呼び出し元は実行UIDに対応するcom.android.shellとする。この端末ではmedia_sessionの書き込みが反映されないことを実機確認した。音量の最小・最大・現在値を取得し、パネル表示中は2秒ごとに同期する。スライダー連続操作は最新値へまとめ、書き込みを直列化する。
- ウィンドウへフォーカスが戻った時、詳細を閉じた時、点灯・消灯・ロック操作が完了した時は、埋め込んだ映像ウィンドウへキーボードフォーカスを戻す。PINを含む入力文字列は取得・保持しない。
- 詳細を閉じている間は上部に「点灯・消灯・ロック・詳細」を表示し、左側詳細を開いた時だけ上部列を隠す。左側の「詳細を閉じる」で戻す。切替時も映像サイズを維持する。
- 詳細は映像の左側に幅320pxのパネルとして展開する。展開・折りたたみでは映像の幅と高さを維持し、外側のウィンドウ幅だけを変更する。モニター内に収まらない場合だけ映像を比率維持で縮小する。
- 2026-10-27: 接続前のコンパネと接続後のミラー表示は同じトップレベルウィンドウを使う。接続時はスマホ画面と上部の操作列を表示し、「詳細」で同一ウィンドウの左側へ既存の端末一覧・設定を展開する。切断時は接続前のコンパネへ戻る。複数端末の映像は選択した1台だけを同じ表示領域へ切り替える。通知領域への格納は維持する。
- 拡大縮小時は映像の縦横比をウィンドウ外形へ反映し、映像の横余白を作らない。最大化もモニターの作業領域内で映像比率を維持する。操作列は詳細を閉じている時だけ表示する。
- 2026-10-27: 消灯時はスマホ側に独立セッションの復帰プロセスを先に起動する。ADB入力のEOFまたは親ヘルパーの終了で物理画面をONに戻す。PC側で切断後にADB命令を送る方式は使わない。点灯・ロックの前に復帰プロセスを取り消し、ロック後の意図しない点灯を防ぐ。
- .NET Framework 4.x / Win32標準コントロール、x64。Windows 10の標準ランタイムを使用する。
- 実行環境ではWindows FormsのRegisterClassがWin32エラー8で失敗した。標準STATICクラスの生成は成功したため、ウィンドウクラス登録を必要としない標準部品を使用する。
- scrcpy 5.0.1の公式Windows x64配布物を同梱する。画面はPhoneDeskへ埋め込む。
- キーボードはUHIDによる物理キーボード入力。日本語変換は端末のIMEが処理する。
- 2026-10-26: scrcpy 5.0.1のscreen.cはUHIDでもSDL_StartTextInputを呼び、WindowsのIMEがキーを消費する。配布用scrcpyのPEインポート名を、同じ引数・戻り値のSDL_StopTextInputへ変更する。元の公式ZIPは保持し、ビルド時に元のインポートが1件のみ存在することを検査する。この配布物はUHID専用で、PC側の文字変換を利用しない。
- adb devices -lを2秒間隔で非同期取得する。WindowsのADBはUSB端末でもusb:属性を返さないため、TCP接続（コロンまたはmDNSの_tcpを含むシリアル）とemulator-端末を除外して自動起動対象とする。
- 表示を手動で閉じた端末は、抜き差しまたは「画面を表示」まで再起動しない。
- エラー終了後は最大3回、10秒以上間隔を空けて再試行。自動起動失敗のループを防ぐ。
- 通知領域で常駐し、Windowsログオン時の起動を設定できる。自動接続のため初回起動時は有効。
- 認証の回避・認証情報の自動入力は行わない。
- インストーラーexeがLocalAppData/PhoneDeskへ展開し、スタートメニューとデスクトップにショートカットを作成する。
- 更新時、ZIP内と既存ファイルのサイズ・SHA-256が一致すれば展開を省く。常駐ADBの同一バイナリを上書きして失敗する問題を防ぎ、共有ADBは停止しない。
- 入力内容やクリップボード、画面はログ・設定に保存しない。
- 入力はユーザーが選択したスマホ側IME方式に統一する。PC側の入力欄・送信ボタン・独自のクリップボード転送処理は追加しない。クリップボード共有はClipboardWatch.javaとWindows側の書き込み専用処理を使用する。
- 点灯・消灯はADB shellの小さなJavaヘルパーから、同梱scrcpyの画面電源APIラッパーを呼び出す。物理画面の電源だけを操作し、ミラー表示を維持する。Windowsのフォーカスやキー送信には依存しない。
- 「ロック」は消灯と別の操作とし、ADB shell権限でWindowManagerのlockNowを呼んで即時ロックする。その後KEYCODE_SLEEPで通常のスリープへ移行する。画面オフだけの既存処理や端末のロック設定は変更しない。
- 「点灯」はKEYCODE_WAKEUPの後で物理画面をONにし、通常スリープからも復帰する。ロックは解除しない。
- UIには説明文・ヒントを表示しない。ボタン名、入力欄、接続状態・エラー、ログオン起動設定のみを表示する。

## 検証
端末一覧の解析、USB限定判定、切断・再接続、手動終了抑制、再試行制限を自動検証する。実機ではADB接続とscrcpy起動を確認する。入力・認証はユーザーの実操作を必要とするため、未確認のものは明記する。
